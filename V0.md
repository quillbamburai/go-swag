# Instructions for v0

You are building **Go Swag Plus**, a client-facing warehouse + logistics control plane.

Pipeline (director-first): iPad sketches in `design-context/` → Cursor synthesizes a v0 brief from those assets + `styles/theme.css` → v0 generates UI → Cursor pulls code and refactors hardcoded colours to CSS variables → Figma MCP reverse-syncs tokens and frames.

Read in this order:

1. This file
2. `brief/product-architecture.md`
3. `styles/theme.css`
4. The prompt in `prompts/` for the surface you are building
5. The stub file you must fill (do not invent a parallel tree)

## Stack

- Next.js App Router
- TypeScript
- Tailwind mapped to CSS variables from `styles/theme.css`
- Import `styles/theme.css` from `app/globals.css`
- Sora for headings, Inter for body (load from Google Fonts or `next/font`)

## Architecture (non-negotiable)

- **Two hubs**, not six pages. Switch hubs in the header. Keep both on `app/page.tsx` (client state is fine).
- Inventory cards combine stock + inbound production. Do not split those into tabs.
- Distribution combines campaign claims + the dispatch table.
- Re-order is a **drawer**. Production status is a **separate drawer**.
- Nothing ships, spends, or substitutes without an explicit client click.

## Visual rules

- Use `var(--color-*)` and `var(--text-*)` / `var(--font-*)` only. No raw hex, no Tailwind palette colours (`red-600`, `slate-900`, etc.).
- Grow `styles/theme.css` when you need semantic roles (e.g. `--color-danger`, `--color-success`, `--radius-*`, `--space-*`). Do not fork a second token file.
- Headings: Sora. UI copy and tables: Inter.
- High-density operational UI. This is a control plane, not marketing.

## File contract

Fill the existing stubs. Add files only under the folders already listed in `README.md`.

Demo copy must use the spec examples (hoodies, Oct 14, Q4 Offsite, water bottles) until real data exists. Mock data lives in `lib/mock-data.ts`.
